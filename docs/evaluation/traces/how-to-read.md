# How to read a trace

Hypothetical scenario with synthetic data only. These traces are generated by
`scripts/build_reports.py` with scripted agents and no API call; a test keeps them equal to what
the engine produces. They are the CLI's own `--export` files.

| Files | Run |
|---|---|
| `uae_health_access-baseline.{json,md}` | The governed baseline (`cascadeguard run uae_health_access`). |
| `uae_health_access-governance-off.{json,md}` | The governed run beside an ungoverned one (`--governance off`): comparison only, never the result. |
| `uae_health_access-replay-rank1.{json,md}` | The identical incident replayed with the rank-1 repair (`--repair <id>`). |

**In each run** (`.json`; the `.md` shows the same as text):

- `actions`: every proposed action, at which minute, by which role, with the engine's verdict
  and, for a rejection, its reason codes (for example `authority_uncertain`,
  `outside_recipient_boundary`). In the ungoverned run, `would_have_been_rejected` lists the
  reasons the governed engine would have rejected an applied action for.
- `rejected_decisions`: whole decisions the engine refused (for example a citation of a clause
  that is not loaded).
- `findings`: what the engine noticed, with each agent statement under a fixed label (agent
  text is never a finding or a legal conclusion).
- `obligations`, `facts_released`, `goals`: what was owed, who learned what when, and which
  recovery goals were met.
- `failures`: the diagnosed coordination failures, each with the clauses considered (every
  clause with its status label) and its qualification: not a confirmed legal or standards gap.
- `loaded_clauses`, `clause_set`, `agents`: what the run was built from.

**In the replay**: which baseline failures the repair removed at their cause, which it only
masked (goal met another way, cause still present), which remain, and any new conflict; the
repair's edits are hypothetical rules, not source clauses, and a repair marked
`requires_authorization` needs human and institutional approval.

Live LLM runs (gate 4) are in `docs/evaluation/gate4/`, with the decision cache that replays them
offline.
